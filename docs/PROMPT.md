# Production prompt

The only supported prompt is defined by INSTRUCTIONS and CRITERIA in backend/models.py.
Its recorded policy ID is `state-action-v6-compact-choice`. This ID identifies saved results;
there is no prompt-version selector or alternate prompt implementation.

## Shared instructions

```text
Which listed face turn should be executed next to solve this Rubik's Cube, within moves_remaining? Goal: each face matches its center. Letters denote fixed-center colors (URFDLB=up/right/front/down/left/back). cube_facelets is row-major URFDLB; faces uses '/' between rows. Outside views; top/right neighbors: U=B/R;R=U/B;F=U/R;D=F/R;L=U/F;B=U/L. Turns: degrees, CW clockwise, CCW counterclockwise, viewed at the named face. HTM: each listed turn=1 move; 30 max.
```

## Actions

- `U`: up 90 CW
- `U'`: up 90 CCW
- `U2`: up 180
- `R`: right 90 CW
- `R'`: right 90 CCW
- `R2`: right 180
- `F`: front 90 CW
- `F'`: front 90 CCW
- `F2`: front 180
- `D`: down 90 CW
- `D'`: down 90 CCW
- `D2`: down 180
- `L`: left 90 CW
- `L'`: left 90 CCW
- `L2`: left 180
- `B`: back 90 CW
- `B'`: back 90 CCW
- `B2`: back 180

## Observation and output

The state contains the authoritative 54-character cube_facelets value, six lossless
slash-separated 3x3 face grids, recent_moves (at most six of this agent's executed moves),
and moves_remaining. Grid orientations use the exact engine conventions described above.
An agent's first request has empty history. Complete executed histories stay internal
for metrics and replay; models do not receive another agent's moves.

The Decisions adapters expose the same instructions and all 18 actions through their
provider's native choice schema. Claude receives equivalent state/question JSON plus
`Return one legal move as schema JSON.` and a strict JSON schema accepting exactly
one property, move, with one of the 18 legal values. No move is extracted from prose or
reasoning, replaced by a probability runner-up, or generated by the reference solver.

The trial ceiling is 30 HTM actions. Claude defaults to low reasoning and a fixed
2,048-token reasoning/completion ceiling. Retries default to zero. Provider route and
settings are recorded as experimental conditions, while old saved results remain readable.
No scramble, optimal solution, heuristic score or successor-state preview enters the
live prompt. Runtime guards validate exact effective identities and legal actions.

These rules preserve comparison fairness. They do not guarantee a response, valid JSON,
a correct action or a solved cube. Historical failures remain evidence rather than being
silently corrected or rerun.
